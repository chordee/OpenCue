# 06 — 資源用量實測

為了判斷「目標主機需要多少規格」而做的實測，不是估算。

## 測試條件

- 環境：WSL2 Ubuntu 24.04，Docker Desktop（16 CPU / 19.2 GiB 可用）
- Stack：db + flyway + cuebot + rqd（完整 sandbox）
- 負載：`load_test_jobs.py simple -n 50 --sleep-seconds 2-5 --batch-size 10`
  （50 個 job、每個 3 frame，共 150 frame）

## 量測結果

### 閒置（啟動完成、無 job）

| 容器 | CPU | 記憶體 |
|---|---|---|
| cuebot | 0.52% | **406 MiB** |
| db | 0.02% | 33 MiB |
| rqd | 0.00% | 3 MiB |

### 負載中（50 job 派發高峰）

| 容器 | CPU | 記憶體 |
|---|---|---|
| cuebot | **40.6%** | **534 MiB** |
| db | 19.0% | 70 MiB |
| rqd | 14.4% | 11 MiB |

### 負載後（frame 陸續完成）

| 容器 | CPU | 記憶體 |
|---|---|---|
| cuebot | 0.62% | 555 MiB |
| db | 0.19% | 80 MiB |
| rqd | 1.35% | 13 MiB |

（`docker stats` 的 CPU% 以「一個核心 = 100%」計算。）

## 結論

**這個負載下，整組 stack 的尖峰是約 620 MiB 記憶體、不到 1 個核心。**

而且目標環境**不會有 rqd**（宿主不算圖），所以實際只需要 cuebot + db：
**尖峰約 600 MiB、約 0.6 核**。

Cuebot 是 Java（Spring Boot），記憶體從 406 MiB 起跳、隨負載緩升到 555 MiB，
**沒有出現爆量**。這是整組裡唯一需要留意的耗用者。

**後續實測**（[`24`](24-派工行為與監控.md)）：兩個節點、一次 500 個 frame 之後，Cuebot 683 MiB、DB 127 MiB，
仍在容器上限（4G / 2G）內。選用的監控 stack（Prometheus + Grafana + exporter）
另外約 130 MiB。

## 對主機規格的判讀

| 規格 | 判斷 |
|---|---|
| 2 GB RAM | 勉強。扣掉 OS 本身的耗用後餘裕很小，不建議 |
| 4 GB RAM | 可行。給 cuebot 容器 2G 上限即充裕 |
| 8 GB 以上 | 充裕，且留得下 CueWeb / 監控那組的空間 |
| CPU | 2 核以上即可；本測試尖峰不到 1 核 |

**重要的但書**：本次只有 **1 台 render node、150 個 frame**。真實農場的
Cuebot 負載會隨「render node 數量 × 同時在跑的 frame 數」上升 ——
每台 RQD 每 5 秒送一次 host report，Cuebot 要逐一處理並寫 DB。
幾十台節點時這個常態負載會明顯高於本測試。

因此上表適用於「評估／試跑／小規模」。若之後接到數十台 Windows 節點，
需要重新量測，特別是 Cuebot 的 Java heap 與 PostgreSQL 的連線數。

## 磁碟

本測試時間太短，看不出成長趨勢。需要留意的是：

- PostgreSQL 的 `db-data`：job / frame 歷史會持續累積。
  Cuebot 會在 job 完成 72 小時後（`history.archive_jobs_cutoff_hours`）
  把它搬到歷史表，但**那是搬移不是刪除，沒有任何自動清除機制**，
  所以 DB 體積會無限成長。詳見 [`11-正式部署風險與待辦.md` 第 6 點](11-正式部署風險與待辦.md#6-postgresql-的資料保留與備份)，
  該節也附了 `pg_dump` 的備份指令
- frame log：由 render node 寫到共享儲存，**不佔宿主空間**，但總量會很可觀
  （每個 frame 一個 .rqlog）

**完整的空間規劃（含實測數字、成長特性與清理策略）見
[`15-空間規劃.md`](15-空間規劃.md)** —— 該節涵蓋建置機器的 build cache、registry、
PostgreSQL、frame log、算圖輸出、Docker 宿主與 Windows 節點本機暫存。
