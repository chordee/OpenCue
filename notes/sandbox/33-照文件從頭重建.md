## 二、照做時卡住或容易出錯的地方

| 步驟 | 狀況 | 處理 |
|---|---|---|
| 01 建立 stack | Compose path 那一格是連結，顯示完整路徑但連結指向 `server/...`，複製到錯的值，部署失敗（`open /data/compose/7/server/opencue.portainer.yml: no such file`） | 改為純文字 |
| 01 建立 stack | 舊的 stack 還在，名稱重複 | 01 補充提醒；舊 stack 的容器掛載了已刪除的目錄，要先移除容器才刪得掉 |
| 01 驗證 | flyway log 最後有 3 行 `duplicate key ... c_task_lock_pk` | 上游 seed 與 migration 重複插入，無害；01 註明，見 [`05` 第 26 項](05-可回饋上游的問題.md#26-全新部署時-seed-資料與-migration-重複插入-task_lock) |
| 02 節點註冊 | **節點永遠註冊不上**：tag 總長度 129 超過上游上限 128 | 工作室的 flyway migration，見 [`32`](32-節點tag長度上限.md) |
| 02 設定 | `rqd-start.bat` 的 `NODE_ROLE` 沒有 EDIT 標記，但文件說每台要確認 | 補上標記 |
| 03 設定 | 用戶端範本的伺服器寫 `linux-server.studio.local`，其他地方是 `opencue-server.studio.local` | 統一 |
| 04 升級 image | 改完環境變數後 **Pull and redeploy** 是灰的 | 要先按 **Save settings**；04 補充按鈕位置與名稱 |
| 04 升級 image | 下載很慢（本機到 GHCR），近一小時才切換 | 04 註明；期間舊容器照常運作 |

刪除 `C:\opencue` 時也遇到兩次阻礙：舊的 RQD 還在執行（工作目錄在裡面），以及工具的保護機制擋下刪除，
最後由使用者手動刪除。這屬於測試環境本身，不影響文件。

## 四、觀察到一次、無法重現：Maya 卡約 11 分鐘

重建後第一次回歸測試，兩格 Maya（14:26:03、14:26:37 開始）都卡在 Arnold 外掛載入，
**同一秒 14:37:30 一起結束**，log 在 Arnold 版本資訊後直接跳到 `00:11:11`。

之後的測試都沒有重現：

| 測試 | 時間 |
|---|---|
| 直接執行，RQD 的精簡環境 | 12 秒（有 `OptiX cache ... LOCALAPPDATA undefined` 警告） |
| 直接執行，補上 `LOCALAPPDATA` / 指向本機空資料夾 | 40 秒 / 20 秒 |
| 直接執行，完整環境 | 14 秒 |
| 農場，單獨一格 / 兩格並行 | 18 秒 / 各 18 秒 |
| 農場，與 Houdini、Nuke 同時執行 | 各 33 秒 |

`LOCALAPPDATA` 不是原因。兩格同時結束，像是在等同一個資源逾時（例如授權或快取的初始化），
推測是全新環境第一次執行時的一次性現象，但無法確認。沒有修改任何設定。
