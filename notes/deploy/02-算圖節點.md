# 02 — 算圖節點（Windows）

專職算圖機與 artist 工作站都要做這一篇。兩者的差異集中在第八節。
artist 工作站另外還要做 [`03-工作站.md`](03-工作站.md)。

---

## 一、目錄結構

所有節點統一使用同一個結構，路徑相同，job 指令才不需要知道每台機器的差異：

```
C:\opencue\
    venv\                Python 虛擬環境（RQD、ocrun）
    tmp\                 RQD 與 frame 的暫存目錄（TEMP / TMP）
    dcc.toml             本機有哪些 DCC 版本、裝在哪  ← node/dcc-windows.toml
    rqd.conf             RQD 設定          ← node/rqd-windows.conf
    rqd-start.bat        啟動腳本          ← node/rqd-start.bat
    rqd-service.log      RQD 的輸出（啟動後自動產生）
```

這裡只放**每台機器本機必要的**東西。frame log、場景檔、算圖輸出、job 呼叫的腳本
都放在網路空間，不要放進 `C:\opencue\`，見 [`README`](README.md) 的「放在本機，還是放在網路空間」。

## 二、【重要】設定檔與腳本一律使用純 ASCII

[`node/`](node/) 底下的所有檔案都是純 ASCII，修改時**不要加入中文**（包括註解）。

| 檔案 | 讀取方式 | 放中文的後果 |
|---|---|---|
| `.bat` | cmd.exe 以 OEM 代碼頁（cp950）解析 | 語法被破壞，例如 `'tlocal' is not recognized` |
| `rqd.conf` | RQD 讀檔時**沒有指定編碼**，使用系統 ANSI 代碼頁 | 繁體中文 Windows（cp950）上 **RQD 啟動即崩潰**（`UnicodeDecodeError`） |
| `.vbs` | Windows Script Host 以 ANSI 代碼頁讀取 | 不可預期 |

本機 sandbox 剛好啟用了 Windows 的「使用 Unicode UTF-8 提供全球語言支援」
（ACP = 65001），所以帶中文註解的 `rqd.conf` 在那台機器上能用，
**一般的繁體中文 Windows 上會失敗**（已用 cp950 解碼實測確認）。

依據：[`notes/sandbox/09` 坑 #13](../sandbox/09-NIMBY與混合機隊.md#坑-13bat-檔必須是純-ascii)、[`17` 場景 23](../sandbox/17-故障排查與常見疏失速查.md#場景-23rqd-一啟動就崩潰報-unicodedecodeerror)、[`05` 第 18 項](../sandbox/05-可回饋上游的問題.md#18-python-rqd-讀取-rqdconf-時沒有指定編碼)。

## 三、安裝

### 1. 前置軟體

| 軟體 | 用途 |
|---|---|
| Python 3.11（Windows 原生版，**不是** WSL，也不是 Microsoft Store 版） | 執行 RQD |
| Visual Studio Build Tools（「使用 C++ 的桌面開發」工作負載） | 編譯 winps |
| OpenCue 原始碼（`git clone` 或複製 repo） | 從原始碼安裝套件 |

### 2. 安裝套件

在 repo 根目錄執行：

```bat
python -m venv C:\opencue\venv
C:\opencue\venv\Scripts\python.exe -m pip install ./proto ./rqd
C:\opencue\venv\Scripts\python.exe -m pip install wmi pywin32
C:\opencue\venv\Scripts\python.exe -m pip install ./notes/deploy/node/ocrun
cd rqd\winps
C:\opencue\venv\Scripts\python.exe -m pip install .
```

**兩個容易漏掉的**：

| 套件 | 沒裝的後果 |
|---|---|
| `wmi`、`pywin32` | RQD **啟動即崩潰**（`No module named 'wmi'`）。rqd 套件沒有宣告這兩個相依 |
| `winps` | RQD 能跑，但**記憶體用量永遠回報 0**，而且沒有任何警告 |

依據：[`notes/sandbox/08`](../sandbox/08-Windows節點實錄.md)。

### 3. 放置檔案

```bat
mkdir C:\opencue\tmp
copy node\rqd-windows.conf  C:\opencue\rqd.conf
copy node\rqd-start.bat     C:\opencue\rqd-start.bat
copy node\dcc-windows.toml  C:\opencue\dcc.toml
```

`dcc.toml` 只列本機**實際有安裝**的版本，見第五節。

## 四、設定 `rqd.conf`

範本的預設值是**專職算圖機**。每台要改的有三項（檔案中標 `EDIT`），
artist 工作站另外還要改兩項（標 `EDIT (workstation)`，見第八節）：

| 項目 | 說明 |
|---|---|
| `OVERRIDE_CUEBOT` | OpenCue 伺服器的主機名稱或 IP |
| `OVERRIDE_HOSTNAME` | 本機的**單段**主機名稱（例如 `RENDER01`，不要 `RENDER01.studio.local`） |
| `RQD_TAGS` | 本機可用的派工標籤，**第一個 tag 決定 allocation**，見下方與第六節 |

**`OVERRIDE_HOSTNAME` 為什麼要單段**：Cuebot 會把節點回報的名稱截成第一段，
再用它回連節點的 8444。那個短名稱必須在 Cuebot 容器內解析得到。
依據：[`notes/sandbox/08`](../sandbox/08-Windows節點實錄.md)、[`04` 坑 #3](../sandbox/04-部署過程.md#坑-3rqd-回報-ipv6-位址cuebot-無法回連)。

### facility

```ini
DEFAULT_FACILITY = local
```

RQD 預設的 facility 是 `cloud`，而用戶端投遞的 job 預設是 `local`。
facility 對不上，節點就**永遠收不到 job，也沒有任何錯誤訊息**。

已在 Windows RQD 上實測：有這一行落在 `local.*`，拿掉這一行則落在 `cloud.general`。
依據：[`notes/sandbox/17` 場景 20](../sandbox/17-故障排查與常見疏失速查.md#場景-20新節點加入後永遠收不到工作)。

### allocation 由第一個 tag 決定

節點**第一次註冊**時，Cuebot 依序檢查節點回報的 tag，
第一個對得上 allocation 的 tag 決定它進入哪個 allocation（`HostManagerService.java:189`）。
所以 `RQD_TAGS` 的**第一個 tag** 很重要：

| 機器 | `RQD_TAGS` 開頭 | 註冊後的 allocation |
|---|---|---|
| artist 工作站 | `desktop` | `local.desktop` |
| 專職算圖機 | `general` | `local.general` |

實測（三台測試節點）：

| `DEFAULT_FACILITY` | `RQD_TAGS` 開頭 | 結果 |
|---|---|---|
| `local` | `general` | `local.general` |
| （沒設） | `general` | `cloud.general` |
| `local` | `desktop` | `local.desktop` |

`OVERRIDE_IS_DESKTOP = True` 也會加上 `desktop` tag，但它排在 `RQD_TAGS` 後面，
**不會影響 allocation**。

allocation 只在第一次註冊時決定，之後修改 `RQD_TAGS` 不會改變。要調整時手動移動：

```bash
cueadmin -force -move local.general -host RENDER01
```

移動後，先前卡住的 job 會自動被撿走。

### 傳給 frame 的主機環境變數

RQD 給 frame 的環境變數非常少（Windows 上只有 `SYSTEMROOT`、`APPDATA`、`TMP` 等幾個）。
範本最後的 `[UseHostEnvVar]` 區段列出要從 RQD 程序額外帶給 frame 的變數：

```ini
[UseHostEnvVar]
ALLUSERSPROFILE
TZ
```

| 變數 | 少了會怎樣（實測） |
|---|---|
| `ALLUSERSPROFILE` | Maya 裡的 Autodesk 授權模組在算完、結束時當掉：frame 仍然成功，但**每格都跳出 Autodesk Error Report 視窗**，而且多花約 15 秒 |
| `TZ` | RQD 把每個 frame 的 `TZ` 寫死為 `PST8PDT`，frame 裡的本地時間是美西時間，**比台灣慢 15 小時**，算圖腳本以日期命名的檔案或資料夾常會變成前一天。列入後改用主機的值；Windows 主機通常沒有 `TZ`，frame 拿到空值，改用 Windows 的時區設定 |

不要加入 `USERPROFILE`、`LOCALAPPDATA`：frame 會讀到登入中 artist 的 DCC 偏好設定與外掛。
依據：[`notes/sandbox/28`](../sandbox/28-Maya結束時跳出錯誤回報.md)、[`29`](../sandbox/29-frame的時區.md)。

## 五、呼叫 DCC：`ocrun`

job 指令不寫 DCC 的安裝路徑，一律透過 `ocrun`：

```
ocrun <產品> <版本> <程式> [參數...]

ocrun houdini 22.0.429 hython P:/proj/render.py
ocrun houdini 22.0.429 husk --make-output-path -f #IFRAME# -n 1 -o P:/proj/out.$F4.exr P:/proj/shot.usd
ocrun maya 2027 Render -r file -s #IFRAME# -e #IFRAME# P:/proj/scene.ma
ocrun nuke 17.0v1 Nuke17.0 -t P:/proj/render.py
```

`ocrun` 從本機的 `C:\opencue\dcc.toml` 查出該版本所在的目錄，執行其中的程式，參數原封不動轉交。

- **所有節點的 job 指令一致，`dcc.toml` 各自指向本機的安裝位置**
  （範本 [`node/dcc-windows.toml`](node/dcc-windows.toml)，改標 `EDIT` 的區段）
- 同一台機器可以並存多個版本，每個版本一行
- `#IFRAME#` 由 Cuebot 在派工時換成 frame 編號
- 版本沒設定或程式不存在時，以 exit 127 結束，frame log 會寫明原因
- 不帶參數執行 `C:\opencue\venv\Scripts\ocrun.exe` 會列出本機設定的所有版本，可用來檢查設定
- 程式本身（[`node/ocrun/`](node/ocrun/)）只用 Python 標準函式庫，Windows 與 Linux 共用。
  Linux 節點的設定檔位置是 `/opt/opencue/dcc.toml`

**frame 找得到 `ocrun` 的前提**有兩個，缺一不可：

- `rqd-start.bat` 把 venv 的 `Scripts` 加進 PATH
- `rqd.conf` 設定 `RQD_USE_PATH_ENV_VAR = 1`，讓 frame 沿用 RQD 的 PATH

砍 frame 時，RQD 會以 `taskkill /T` 結束整個程序樹，DCC 程序也會一起結束（已實測）。
依據：[`notes/sandbox/26`](../sandbox/26-ocrun取代wrapper.md)。

### 授權伺服器寫在 `dcc.toml`

RQD **不會繼承使用者的環境變數**。DCC 需要的授權設定寫在 `dcc.toml` 的 `[env]`，
所有 DCC 都會帶上。範本中已經預留（取消註解後填入實際位置）：

```toml
[env]
ADSKFLEX_LICENSE_FILE = '@license-server.studio.local'
foundry_LICENSE = '4101@license-server.studio.local'
solidangle_LICENSE = '5053@license-server.studio.local'
```

**Arnold 一定要設定 `solidangle_LICENSE`**（已實測）。沒有設定時，每一格 Arnold 都會出現
`license checkout error` 並中止算圖。本機測試時，桌面上開的 Maya 能正常算圖，
是因為使用者環境裡有這個變數，但 RQD 不會把它傳給 frame。

更危險的是，Arnold 中止時 `Render.exe` 仍然回傳 0，frame 被當成成功，實際上沒有任何輸出。
`ocrun` 因此會檢查 Maya 的輸出，出現這類錯誤就讓 frame 失敗，見下一小節。
其他授權（`ADSKFLEX_LICENSE_FILE`、`foundry_LICENSE`）尚未實測。
依據：[`notes/sandbox/30`](../sandbox/30-Arnold授權與假成功.md)。

### 看起來成功、其實失敗的 frame

有些 DCC 出錯時仍回傳 0。`ocrun` 會逐行檢查輸出，出現已知的錯誤字串就讓 frame 以 exit 1 結束，
並在 log 最後寫明原因（`[ocrun] failing the frame, the output reported: ...`）：

| 產品 | 檢查的字串（不分大小寫） |
|---|---|
| Maya | `aborting render because`、`license checkout error` |

字串定義在 [`node/ocrun/ocrun.py`](node/ocrun/ocrun.py) 的 `PRODUCT_FAIL_PATTERNS`。
新增前要先確認該字串只會在真正失敗時出現，否則會把正常的 frame 判成失敗。

### 關閉 DCC 的當機回報視窗

Maya 算圖時若當掉，Autodesk 的錯誤回報視窗（`cer_dialog.exe`）會出現在桌面上：
工作站上會跳到 artist 面前，專職算圖機上則沒人關閉。

實測發現，**即使算圖成功也會跳出**：Maya 裡的授權模組在結束時當掉，原因是 frame 缺少
`ALLUSERSPROFILE`。解法是 `rqd.conf` 的 `[UseHostEnvVar]`，見第四節。

`ocrun` 執行 Maya 時會設定 `MAYA_DISABLE_CER=1`，但它**只關得掉 Maya 本體的回報**。
授權模組有自己的回報程式，不受這個變數影響（實測）。
Houdini、Nuke 的當機視窗行為**尚未查證**。
依據：[`notes/sandbox/28`](../sandbox/28-Maya結束時跳出錯誤回報.md)、[`25` 第五節](../sandbox/25-Maya內投遞.md#五人工測試中發現的問題)。

### 暫存目錄

RQD 只傳 `TMP` 不傳 `TEMP`，Nuke 找不到 `TEMP` 會退回 `C:\temp` 而全部失敗。
`ocrun` 會以 `TMP` 補上 `TEMP`，執行 Nuke 時另外設定 `NUKE_DISK_CACHE`（`TEMP` 底下的 `nuke`）。
依據：[`notes/sandbox/17` 場景 7](../sandbox/17-故障排查與常見疏失速查.md#場景-7nuke-算圖全面失敗報-unable-to-create-disk-cache)。

## 六、派工標籤（`RQD_TAGS`）

```ini
# 專職算圖機
RQD_TAGS = general houdini22 houdini_22_0_429 maya2027 maya_2027 nuke17 nuke_17_0v1
# artist 工作站
RQD_TAGS = desktop general houdini22 houdini_22_0_429 maya2027 maya_2027 nuke17 nuke_17_0v1
```

| 標籤 | 意義 |
|---|---|
| `desktop` | artist 工作站，放在第一個才會進 `local.desktop` |
| `general` | 一般派工池 |
| `houdini22` | 鬆綁定：有任一個 Houdini 22 版本 |
| `houdini_22_0_429` | 嚴格綁定：有這個確切版本 |

- 只列本機**實際裝了**、而且 `dcc.toml` 裡**有設定**的版本
- **Cuebot 的 tag 比對是「或」**：layer 只要有一個 tag 對上就會派過來。
  所以 service 或 layer **不要同時帶 `general` 和版本 tag**，否則會被派到沒裝那個版本的機器

實際投遞時，**用 service 指定版本**（伺服器端 `OPENCUE_INIT_SERVICES` 建立），
不要在每個 layer 手寫 tag。依據：[`notes/sandbox/12`](../sandbox/12-真實DCC算圖.md)、[`21`](../sandbox/21-Service與資源模型.md)、[`17` 場景 19](../sandbox/17-故障排查與常見疏失速查.md#場景-19job-被派到沒有該-dcc-版本的節點)。

## 七、啟動腳本 `rqd-start.bat`

腳本做了三件事，**不要省略**：

1. **固定工作目錄**為 `C:\opencue`：否則 Linux 風格的路徑會解析到當下所在的磁碟機
2. **重設 PATH、TEMP、TMP**：不繼承啟動者的環境。從 Git Bash 等開發工具啟動時，
   Unix 工具會蓋掉 Windows 內建指令（例如 `timeout`），造成 frame 行為怪異。
   PATH 只保留 Windows 系統目錄與 venv 的 `Scripts`（讓 frame 找得到 `ocrun`）
3. **先啟動 RQD，等 20 秒，再啟動 CueNIMBY**：順序顛倒會得到 `failed to lock host`

每台要確認的只有 `NODE_ROLE`：

| 值 | 用途 |
|---|---|
| `set NODE_ROLE=workstation` | artist 工作站：會啟動 CueNIMBY |
| `set NODE_ROLE=render` | 專職算圖機：不啟動 CueNIMBY |

（`.bat` 的 `set` 那一行不要加行內註解，後面的空白與文字會變成變數值的一部分。）

依據：[`notes/sandbox/08`](../sandbox/08-Windows節點實錄.md)、[`09`](../sandbox/09-NIMBY與混合機隊.md)、[`17` 場景 11](../sandbox/17-故障排查與常見疏失速查.md#場景-11cuenimby-啟動報-rqdclientexception-failed-to-lock-host)、[13](../sandbox/17-故障排查與常見疏失速查.md#場景-13算圖指令行為怪異windows-內建指令被別的程式取代)、[14](../sandbox/17-故障排查與常見疏失速查.md#場景-14frame-log-檔案憑空消失或跑到別的磁碟機)。

## 八、專職算圖機與工作站的差異

範本的預設值是專職算圖機，工作站要改粗體的項目：

| 項目 | 專職算圖機（範本預設） | artist 工作站 |
|---|---|---|
| `OVERRIDE_IS_DESKTOP` | `False` | **`True`** |
| `RQD_TAGS` 開頭 | `general` | **`desktop`** |
| `NODE_ROLE`（`rqd-start.bat`） | `render` | **`workstation`** |
| CueNIMBY | 不需要 | **要裝**（[`03-工作站.md`](03-工作站.md)） |
| 啟動方式 | Windows 服務 | **使用者登入時** |
| 註冊後的 allocation | `local.general` | `local.desktop` |

### 工作站：必須在使用者登入時啟動，不能用 Windows 服務

CueNIMBY 與網路磁碟機代號都**綁定使用者的登入工作階段**。
Windows 服務跑在 session 0，看不到使用者的磁碟機對應。

做法（擇一）：

- IT 以 GPO 派送「使用者登入時觸發」的排程工作，執行 `C:\opencue\rqd-start.bat`
- 或把 [`node/rqd-start-hidden.vbs`](node/rqd-start-hidden.vbs) 放進使用者的啟動資料夾
  （`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`），不會留下命令列視窗

**兩種方式都尚未實測**（本機沒有管理員權限，寫入啟動資料夾也被擋下）。

### 專職算圖機：Windows 服務，但要先確認網路磁碟機

服務的好處是開機就啟動、不需要有人登入。**但有一個必須先確認的問題**：

> 磁碟機代號綁定於登入工作階段，服務看不到使用者建立的 `H:`、`P:` 等對應。
> 而專案檔內部是用磁碟機代號引用路徑，改不了。

第一台專職算圖機上線前，**以服務帳號執行一個讀寫網路磁碟機代號的測試 job**。
不通的話，對策是：

- 服務啟動前以服務帳號執行 `net use` 建立對應
- 或由 IT 以 GPO 為服務帳號建立持續性的磁碟機對應
- 或該機器改成「自動登入 + 登入時啟動」，比照工作站

**尚未實測。** 依據：[`notes/sandbox/11` 第 2 點](../sandbox/11-正式部署風險與待辦.md#2-網路磁碟機代號可用但有一個例外)。

## 九、防火牆

| 方向 | Port | 用途 |
|---|---|---|
| 出站 | 8443 | 連到 OpenCue 伺服器 |
| **入站** | **8444** | **Cuebot 回連本機派發 frame** |
| 出站 | 445 | 共享儲存（SMB） |

**入站 8444 最容易漏**，Windows 防火牆預設會擋。漏掉的症狀是
「host 顯示正常，frame 永遠卡在 RUNNING、沒有 log」。

```bat
netsh advfirewall firewall add rule name="OpenCue RQD" dir=in action=allow protocol=TCP localport=8444
```

需要管理員權限。**尚未在實機驗證。**

## 十、上線驗證（第一台務必全部做）

1. 節點已註冊，狀態 UP，alloc 前綴是 `local`：

